【统一入口: steamos.sh】 (不知道跑哪个脚本时, 先跑它)
======================================================================
  用法:  cd 到本目录 && bash steamos.sh        (或双击 steamos.desktop)

  它把本包 40+ 条能力收进一个菜单, 按用途分组:
     体检与状态 / 重装与升级恢复 / 应用安装与便携化 / 故障修复 / 诊断取证 / 维护与发布

  每项都标了性质, 一眼能看出"敢不敢点":
     只读 = 不改任何东西(体检、诊断、自检) —— 随便跑
     sudo = 会提权、要输密码(装东西、改系统)
     交互 = 需要你在终端前(会问确认、或者可能改盘)

  不想开菜单也行, 每条都能直接敲:
     bash steamos.sh list            列出全部命令
     bash steamos.sh doctor          体检(等价于 doctor.sh)
     bash steamos.sh setup 3         只跑第 3 步(参数原样转给主脚本)
     bash steamos.sh selfcheck       自检: 注册表↔文件一致 / 跑的是哪一份 / 快照新旧
     bash steamos.sh help            完整用法

  两个"发布用"的命令:
     bash steamos.sh pack            打发布包 dist/steamos-toolbox-<版本>.tar.gz
     bash steamos.sh dist-verify     把包解到临时目录实跑一遍, 验证它真的自包含

  设计上的一条保证: 它自己**不提权**、也不会被写进 sudoers —— 需要 root 的仍由
  各脚本自己 sudo。所以它不会成为新的提权口子(改脚本时请保持这一点, check.sh 有断言)。
  另外: 在管道/定时任务里(没有终端)它**不会挂住等密码**, 只会把该跑的命令打印出来。

【本备份包用途】
重装 SteamOS(或 Arch 系)后, 在无 AI 辅助的环境下重建开发环境。
所有脚本已自包含, 不依赖旧机器任何文件, 解压到 Downloads 即可运行。

【最核心的文件: steamos-setup.sh】 (唯一必需)
======================================================================
这是一个"一键配置脚本", 已内嵌背键守护进程源码、输入法配置、
Steam 游戏启动工具、dsh 安装逻辑等全部内容(完全自包含)。

用法(在解压目录打开终端运行):
  1) 先看状态:    bash steamos-setup.sh --status
  2) 分步安装(推荐, 便于定位错误):
       bash steamos-setup.sh 1    # archlinuxcn 源
       bash steamos-setup.sh 2    # 输入法: 【已禁用】不改动系统输入法(保留步号, 空跑)
       bash steamos-setup.sh 3    # WorkBuddy (AUR包, 装/opt+electron, 完了自动自持化到 /home)
       bash steamos-setup.sh 4    # GPD Win5 背键(自动检测机型, 非Win5跳过)
       bash steamos-setup.sh 5    # Decky Loader
       bash steamos-setup.sh 6    # 游戏: GE-Proton + 鸣潮/终末地辅助
       bash steamos-setup.sh 7    # DeepSeek Harness (dsh, 补充AI CLI, 走npm国内镜像)
       bash steamos-setup.sh 8    # rootfs 瘦身(可选, 清 locale/man/doc/缓存)
       bash steamos-setup.sh 9    # TDP 控制(SimpleDeckyTDP, 插电/离电分档)
       bash steamos-setup.sh 10   # 换境内NTP(加速开机, 解决 atomupd 白等20秒)
       bash steamos-setup.sh 11   # GPU 加速建议(DLSS/FSR/XeSS, 按显卡自动提示)
       bash steamos-setup.sh 12   # 升级后自愈服务(开机自动重建被系统升级冲掉的配置)
       bash steamos-setup.sh 13   # wiliwili (B站客户端, flatpak 用户级)
         bash steamos-setup.sh 14   # LocalSend (局域网传文件; 附带放行防火墙 53317)
         bash steamos-setup.sh 15   # markdown 阅读器 glow (静态二进制落 /home; 顺带注册 .md 双击打开)
         bash steamos-setup.sh 16   # Firefox Nightly (官方 tar.xz 解到 /home, 自带更新器扛原子升级)
  3) 或一次全量:  bash steamos-setup.sh
  4) 复查:        bash steamos-setup.sh --status

断点续传(2026-09-08 起):
  - 中断后重跑同一条命令会跳过已完成步骤, 从断点继续。
  - 进度记在 ~/.cache/steamos-setup/state; --reset 清进度; --force 强制重跑(FORCE=1 写在 sudo 前面会被 env_reset 剥掉, 用参数形式)。
  - --adopt 只检测不安装(把本机已达标的步骤登记为完成)。

系统大版本升级后恢复(2026-09-09 起, 重要):
  - SteamOS 用 A/B 原子更新, 大版本升级会整块替换 rootfs 镜像,
    /etc 与 /usr 下的修改(含 pacman 装的包)全部被覆盖。
  - ⚠️ 但 /opt、/root、/srv、/nix 是 bind-mount 到 /home 分区
    (/home/.steamos/offload/*) → 这些路径下的东西**同样幸存**, 别当成被冲。
    (注意: /usr/local **不在**这个清单里! 它属于 /usr, 升级会被冲 —— 2026-09-25 实测纠正,
     以前本文把它错列为幸存。自查: findmnt -no SOURCE --target <路径>, 与 `--target /` 不同才算 offload。)
    修复过的例子: WorkBuddy 主体(/opt)、Firefox Nightly 与它的入口(~/.local)。
  - 升级后跑这一条即可自动恢复:
        sudo bash steamos-setup.sh --after-upgrade      (等价 restore)
  - 它会: 自动检测版本变化 → 逐个复核落地物 → 只重建被冲掉的, 完好的跳过。
  - 两个前提: ① 需联网(pacman 重装包) ② rootfs 需余量(建议 >600MB, 不足先跑
    sudo bash free-rootfs.sh --apply)。
  - 幸存不用管: 游戏本体 / GE-Proton·DW-Proton / Steam 前缀 / Decky 插件 /
    快捷方式 / 输入法 dconf 配置 / 脚本进度文件 / ~/.local 下的自持化应用。
  - 说明: 步骤[12] 的自愈服务只能补 /etc 下的配置项, 装不了 pacman 包,
    且其 sudoers 也在 /etc(升级必被冲) → 大版本升级后仍要手动跑一次上面那条。

前提:
  - 已进入 KDE 桌面、能联网。
  - 每步需 root(自动 sudo, 在终端输密码)。
  - 全程联网下载。第6步游戏本体需你自行从备份放回下载目录。

注意事项:
  - [2] 装完需注销重登使输入法生效。
  - [3] WorkBuddy 装到 /opt(818M)+electron(/usr), 装前确认 rootfs 空间(脚本会预检)。
        装完会自动"自持化"(见 install-workbuddy-home.sh): 入口和运行时搬进 /home,
        与 /usr、pacman 解耦 → 下次大版本升级后直接可用, 不用重装、不再是沙箱环境。
  - [4] 只在检测到 GPD Win5 时执行; 换机型重装自动跳过。
  - [6] 游戏需在 Steam 里手动"添加非Steam游戏"指向启动器 exe 后,
        python3 steam-launch-games.py 才能写入启动选项(该工具在脚本运行时生成)。
        本步会自动修复鸣潮启动器黑屏(WPF AllowsTransparency bug, patch launcher_main.dll);
        启动器更新后会还原 dll, 黑屏复发时重跑一次本步即可。
  - [7] dsh 固定版本0.1.2-rc.1(开发者预览会破坏兼容), 升级改脚本顶部 DSH_VER。
  - [9] TDP 默认档位: 插电 75W / 离电 40W; 改默认值用 TDP_AC=xx TDP_DC=xx 变量。
  - [10] 换境内 NTP: 默认阿里+腾讯; 改默认值用 NTP_SERVERS='...' 变量。
         开机慢的元凶通常是 atomupd 等 NTP 校时最多 20 秒(默认 arch.pool 境内延迟高)。
  - [11] GPU 加速建议(纯提示, 无落地物): 按显卡自动给出 DLSS/FSR/XeSS 建议。
         AMD 卡提示 FSR(8060S/7900XTX 当前不能用 FSR4, 那是 RDNA4 专属; 用 FSR3.1/系统级FSR);
         N 卡提示 DLSS 4.5 并引导走 Bazzite(官方 SteamOS 不支持 N 卡);
         Intel Panther Lake(Xe3/Arc B3xx)提示 XeSS 硬件加速(同样引导走 Bazzite)。
  - [12] 升级后自愈服务: SteamOS 大版本升级(如 3.8→3.9)会整块替换 rootfs,
         把脚本写进 /etc 的系统级修改(背键/inputplumber/NTP/WorkBuddy IME/LocalSend
         防火墙)全部冲掉。本步放一个 user 服务在 /home, 开机自动检测并重建这些被冲掉的配置。
  - [14] LocalSend: 官方 AppImage 解到 /home(不占 rootfs; 不用 tar.gz —— 那个依赖
         系统 gtk3)。⚠️ 装好却"搜不到对端" ≠ 装失败, 是防火墙没放行 53317/tcp+udp,
         本步会自动放行, 并把这条规则登记进自愈清单(升级后自动重建)。

【rootfs 磁盘告急专用】
free-rootfs.sh
  - rootfs 只有 5G, 官方镜像本身就吃 4.2G, 属于结构性紧张。
  - 注意: 清 pacman 缓存/日志/coredump 完全无效(那些早已 offload 到 p8);
    删 WorkBuddy 也无效(它的 776M 全在 /opt, 同样在 p8)。
  - 真正有效: ①btrfs 元数据平衡(+334M, 零风险) ②删 gcc/孤儿包(+212M)
              ③删 firefox(+290M; 若已按下面装了 Firefox Nightly 到 /home,
                删掉不影响用浏览器) ④zstd 重压缩 /usr(+数百M~1G)
  - 用法: bash free-rootfs.sh                 # 只体检
          sudo bash free-rootfs.sh --apply    # 执行安全项
          sudo bash free-rootfs.sh --apply --with-firefox --with-opencv --compress
  - 前置: 需 steamos-readonly disable(脚本自动处理)。

【多机型兼容】(v1.3.0 起统一为设备画像层, --device 免root快查)
  - 画像: amd-handheld-gpdwin5(主目标) / amd-handheld / amd-desktop /
          intel-handheld(引导Bazzite) / intel-nvidia-desktop(引导Bazzite) / unknown
  - 不支持机型在安装前弹确认门禁; 未来机型适配统一加在 profile_extra()
  - 自动识别: GPD Win5 / AMD 台式独显 / N 卡机器 / Intel 核显(含 Panther Lake)。
  - 背键[4]只在 Win5 上执行; TDP[9]只在 APU/核显上执行(台式独显自动跳过)。
  - N 卡 / Panther Lake 核显机器装不了官方 SteamOS, 脚本会引导走 Bazzite。

【可选组件安装.sh】(必装主线之外的增强项, 带菜单)
======================================================================
  用法: bash 可选组件安装.sh        (或在"重装后先运行我"里选 y; 或用 steamos.sh 菜单的 apps)
    当前条目:  微信 / Clash Verge Rev / 任意 deb 便携化 / DeepSeek Harness 桌面版
                / WPS Office / 鸿蒙字体 HarmonyOS Sans / NextKde 桌面外壳
  - 微信: 官方原生版沙盒封装 wechat-universal-bwrap, 自动补中文字体。
  - Clash Verge Rev: 上游**只发 deb/rpm, 没有 AppImage**(直装 deb 会进 /usr → 升级被冲),
    所以走"拆 deb → 整棵树搬进 ~/.local/opt/clash-verge"(保留包内 usr/ 结构)。
    ⚠️ 它唯一会被升级冲掉的是 Tauri 的 WebView 库 webkit2gtk-4.1(在 /usr):
       装的时候会一并装上; 升级后由自愈链自动补回(见 fix-opt-deps.sh),
       入口也会自检缺库并打印装回命令 —— 不会"点了没反应"。
  - 任意 deb 便携化 (install-deb-portable.sh): 上面那套套路的**通用版**。
    给自己手里的任意 .deb(本地文件或 URL), 它会拆包、装进 ~/.local/opt/<名>,
    入口/桌面项/图标全在 /home → 扛原子升级、一字节不占 rootfs。
    有图形界面时用 kdialog 引导选文件与主程序; 另有 --check(升级后体检)/--remove(卸载)。
  - Firefox Nightly: **已提为必装步骤[16]**, 不在本菜单里了。
    (官方包解到 /home —— 不占 rootfs、扛原子升级, 且目录可写 → 自带更新器能真自更新;
     想回收系统 firefox 那 290M: bash install-app-home.sh firefox-nightly --remove-system)
  - DeepSeek Harness 桌面版: 官方 AppImage 解到 /home(刻意不用 deb)。
    ⚠️ 它推荐的内核版本(包内 version-recommend.json, 当前 0.1.5-rc.3)高于本包
    step[7] 固定的 dsh 版本(0.1.2-rc.1), 而桌面版会优先用已装的 CLI 核心
    → 装完务必看脚本打出的版本提示。
  - WPS Office 中文版: 走官方 deb 装到 /opt/kingsoft(该 deb 的 control 明写
    `Relocations: /opt/kingsoft`, 装在 /opt 既不占 rootfs 又扛升级)。
    当前版本 12.1.2.28080(545MB / 装后约 2.07GB); 官方现行取源带时间戳签名,
    脚本已按官方方案构造, 老通道自动兜底。
    ⚠️ 别用 AUR 的 wps-office / wps-office-cn —— 两者都把 2GB 重定位到
    /usr/lib/office6(rootfs), 必炸。
    装前必须完全退出 WPS; 首次会顺带补运行库(glu 等)与中文字体。
  - 鸿蒙字体 HarmonyOS Sans: 装进 ~/.local/share/fonts(扛原子升级), 配置写进
    ~/.config/fontconfig/conf.d/ —— 不覆盖你已有的 fonts.conf。
    ⚠️ 华为官方 zip 直链带时间戳签名、会过期, 所以脚本没写死地址:
       先下好 zip, 再 HARMONY_ZIP=/路径/xxx.zip bash install-harmony-sans-home.sh
       或 HARMONY_URL='https://...zip' bash install-harmony-sans-home.sh
    monospace(终端/代码字体)刻意不动 —— 鸿蒙是比例字体, 顶替会让等宽错乱。
  新增条目: 只需 ①install_xxx() ②注册表(MENU_ORDER/NAME/PKGS[/CHECK]) ③case 分支。

【备用脚本】(steamos-setup.sh 已覆盖同样功能; 以下供单步/手动补救用)
======================================================================
install-app-home.sh <app>
  - 三个"下载便携包 → 装进 /home 或 /opt"的安装器共用一个引擎:
      firefox-nightly   官方 tar.xz   → ~/.local/opt/firefox-nightly
      dsh-desktop       官方 AppImage → ~/.local/opt/deepseek-harness-desktop
      wps-office        官方签名 deb  → /opt/kingsoft + ~/.local
    骨架只写一遍, 各应用只贡献一段 profile; **仍是单文件, 可单独拷到新机器**。
  - 共同点: 准原子替换(旧树先挪 .prev, 校验通过才删; 失败回滚) + 版本标记
    → 重跑不会白下载/白复制(WPS 那 2GB 尤其重要); 入口/桌面项/图标一律另存 ~/.local,
    所以原子升级后菜单照样在。已是同版本时只补入口与桌面项, 不动本体。
  - 为什么这么选发行物(每个都是踩过坑的):
      · Firefox: pacman/AUR 版在 /usr(rootfs) 升级被冲; Mozilla 只发 tar.xz(原生无沙箱),
        解到 /home 后目录可写 → 自带更新器能真正自更新, 还能反手回收系统 firefox 的 290M。
      · dsh 桌面版: 官方 deb 依赖 libappindicator3-1 + libwebkit2gtk-4.1-0 + libgtk-3-0,
        SteamOS 都没有; AppImage 自带运行时。入口自动选 FUSE 直跑(应用内自更新可替换自身)
        或解压树兜底(不需要 libfuse2)。
      · WPS: AUR 的 wps-office 与 wps-office-cn 都把 2GB 重定位到 /usr/lib → 必 ENOSPC;
        而这个 deb 的 control 写着 Relocations: /opt/kingsoft(/opt 是 bind-mount 到 home
        分区的, 既不占 rootfs 又扛升级)。桌面项必须同时改 Exec 与 TryExec ——
        只改 Exec 的话 TryExec 找不到会把整个菜单项隐藏掉。
  - 用法: bash install-app-home.sh --list                      # 列出支持的 app
          bash install-app-home.sh firefox-nightly             # 安装/修复(幂等)
          bash install-app-home.sh wps-office --check          # 只读自检
          bash install-app-home.sh dsh-desktop --force         # 强制重装(仍用缓存)
          bash install-app-home.sh firefox-nightly --remove-system  # 卸系统 firefox 回收 290M
          bash install-app-home.sh firefox-nightly --lang en-US     # 换英文原版
          bash install-app-home.sh dsh-desktop --version v0.17.1    # API 不可达时钉版本
          环境变量: MIRROR=https://镜像 REFETCH=1(强制重新下载)
                    FFN_MIRROR=https://…(firefox 自备镜像)  WPS_DEB=/路径/x.deb
  - ⚠️ dsh 桌面版包内建议的 CLI 版本(0.1.5-rc.3)高于本包 step[7] 固定的 0.1.2-rc.1,
    而桌面版"如已装 dsh 则优先用安装版本" → 装完务必看脚本打出的版本提示再决定。
  - 装前若 WPS 在运行会拦下(官方 preinst 也是先 killall); 首次会补运行库与中文字体。

install-harmony-sans-home.sh
  - 把鸿蒙字体(HarmonyOS Sans)装成系统字体, 装进 ~/.local/share/fonts → 扛原子升级。
  - 为什么不用 AUR 的 ttf-harmonyos-sans: 它装到 /usr/share/fonts(rootfs) 升级必被冲,
    且它的取源是华为 CDN 的签名链接(带时间戳+哈希)会过期。本脚本改为自备 zip/URL。

【AUR / pacman 装包失败的几个常见"假象"】 (2026-09-26 现场整理; 多数不是包坏了)
  0) "错误：未能同步所有数据库（无法锁定数据库）"
     —— 这是**锁**, 不是源坏了! 有另一个 pacman 在跑(常见: 自动恢复链正在补开发文件,
        或你自己另开了一个终端在装东西)。
     怎么确认: pgrep -x pacman -a        → 看有没有活着的 pacman
     怎么办: 等它跑完即可。脚本现在会**自动等 180 秒**(PACMAN_LOCK_WAIT=秒数 可调),
             等到了就继续; 等不到会告诉你持有者是谁。
             **不要**急着删 db.lck —— 那会让两个 pacman 同时改库, 比等更危险。
  1) "文件系统中已存在 /opt/xxx/..." + "发生错误，没有软件包被更新。"
     —— 这是**孤儿文件**, 不是包损坏、也不是网络。
     为什么: workbuddy 装 /opt/WorkBuddy、微信装 /opt/wechat-universal, 而 /opt 是 offload
     (实际在 /home 分区)。原子升级整块换 rootfs 时, /opt 里的文件**幸存**、/usr 里的
     入口/运行时**和 pacman 的安装台账一起被冲掉** → 变成"文件在、台账没了"。
     再装同一个包, pacman 看到文件已存在就拒绝覆盖, 于是报这句。
     怎么确认(一条): pacman -Qo /opt/WorkBuddy/app.asar.unpacked/resources/trayTemplate.png
                     → 回"没有软件包拥有 ..." 就是它。
     怎么办: 脚本已自动兜底(判定为孤儿后带 --overwrite 重试一次, 并在日志里说明)。
             手工等价: yay -S --overwrite='*' workbuddy   (或 paru 同理)
             **别**养成所有 pacman 都加 --overwrite 的习惯 —— 那样会盖掉真实的包间冲突。
  2) "error sending request for url (https://aur.archlinux.org/rpc): unexpected EOF"
     —— 这是 **AUR 站点本身连不上**(DNS 污染/代理规则没覆盖/被墙), 跟本脚本无关。
     git 能拉、网页能开 ≠ aur.archlinux.org 能连, 它是独立域名。
     换个网络/DNS 或补代理规则再来; 排查: curl -v https://aur.archlinux.org/rpc
  3) "fatal error: zlib.h/string.h：没有那个文件或目录" (AUR 编译到一半挂)
     —— SteamOS 镜像裁掉了 /usr/include 的开发文件(pacman 却显示"已装")。
     先跑: bash fix-missing-dev-files.sh   (体检; sudo ... --apply 补齐)

【升级后自愈为什么没动静? 先查免密】(2026-09-26 现场; 这条最容易被忽略)
  - 现象: journalctl --user -u steamos-self-heal.service 里刷
      "deck : a password is required ; COMMAND=/usr/bin/bash /opt/steamos-backup/steamos-setup.sh 3"
      "[自愈] 步骤 3 未执行(需免密 sudo, 见 steamos-setup.sh 12)"
  - 原因: 我们的免密规则在 /etc/sudoers.d/zz-steamos-self-heal, 而 **/etc 属于 rootfs,
          原子升级会连它一起冲掉**。规则一没, 自愈链就动不了。
  - **更要紧的是这里有个死循环**: 恢复免密这件事本身要跑步骤[12], 而步骤[12] 要 root
    → 免密没了就永远自举不起来, 自愈服务每 20 分钟失败一次, 一直循环。
  - 所以升级后**第一个要跑的是步骤[12]**(唯一必须人工输密码的一步)。
    **优先用仓库里那份**(不是 /opt/steamos-backup 那份): 反正要输密码、无风险,
    且仓库版的步骤[12] 会顺手把过期快照刷新成最新; 免密还活着时才用快照那份(免密跑):
        sudo bash <仓库路径>/steamos-setup.sh 12
        sudo bash /opt/steamos-backup/steamos-setup.sh --after-upgrade
  - ⚠️ **警惕这一行**: "[跳过] 12 升级后自愈服务 —— 已完成于 <日期>"
    它看起来很正常, 但当规则不全/快照过期时, 跳过就等于**什么都没修**。
    (2026-09-27 真机踩到: 新增第三条免密规则后, 落地判据没跟着改 → 永远跳过。
     已修, 并加了自动断言防止再犯。) 想显式强制重跑加 --force:
        sudo bash <仓库路径>/steamos-setup.sh 12 --force
    (步骤[12] 不装包、不刷仓库 —— 补齐器正持锁下载时也能跑, 不会被"无法锁定数据库"挡住)
  - 一条命令看清"是规则丢了还是快照丢了": sudo bash /opt/steamos-backup/diag-sudo-selfheal.sh

3. 目录布局:
   - check.sh          自检脚本(bash -n 全部 + 关键不变量断言, 只读免root)
   - verify-upstreams.sh 上游依赖体检(只读联网; 发布前/重装前跑一次,

   - tools/            可选放一个 shellcheck(.exe) 在这里, check.sh 会自动用它
   - archive/          历史版本存档(0909 原版 / lean 精简版), 不会被执行
   - disabled/         按约束禁用的输入法相关脚本存档
   - steamos-nix/      nix 探路分支(已冻结, 主线不依赖; 完整取舍见 README.md §八;
                       它的两大产出已被主线吸收:
                       "什么会被冲掉"的分区表 → 见本文件顶部的第一条铁律;
                       鸿蒙字体打包踩的坑 → 做可选组件鸿蒙字体时原样复用)

4. 健壮性修复(2026-09-24, 全部脚本 shellcheck warning 级 = 0):
   - 递归删除路径加非空护栏(${VAR:?}) —— 变量为空时宁可报错, 也别 rm -rf "/"
   - local 声明与赋值分离(避免返回值被掩盖)
   - 移除未使用变量; ls|grep 改 glob 循环; find|xargs 改 -exec {} +
   - 大文件下载一律固定缓存目录(别用 mktemp: 随机名会让 -C - 续传失效)
   - GitHub 资源一律"镜像优先"; 注意 ghfast/ghproxy.net **不代理 api.github.com**,
     API 链里只留 gh-proxy.com
   - 递归删除/镜像/入口生成这类"重复但不该抽公共库"的逻辑, 用 check.sh 断言防漂移
     (取舍理由见 SCRIPT-MAINTENANCE §9.4)

   发布前额外跑一次 `bash verify-upstreams.sh`(确认上游没变)。
